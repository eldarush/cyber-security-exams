Cookies — מה מבדיל HttpOnly מ-Secure?

סדר החלופות מתערבב בכל פתיחת עמוד. המפתח המוצג מתאים לסדר הנוכחי. אותיות בתוך הסברים מיובאים מתייחסות לשאלון המקורי — יש לזהות את התשובה לפי תוכנה.

ביטחון במיומנות: 77/100 · מדד שיפוטי, לא אחוז הסתברות לניסוח הזה. איך חושב הציון?

מיומנות: XSS מול סשן וטוקן CSRF. משפחת הנושא הופיעה ב-15/18 מועדים וב-5/7 מועדי ב׳; נמשכה מא׳ לב׳ ב-4/6 זוגות שבהם הופיעה בא׳; במועדי ב׳ של קיץ: 3/3. למיומנות המתועדת יש סימוכין ב-5 תאריכים שונים. משפחת המיומנות ממופה גם באוקטובר 2026; יש לבדוק את השאלה המקורית כדי להבחין בין פעולה זהה למושג קרוב. השאלה מתרגלת וריאציה של מיומנות מתועדת; המספר אינו סיכוי לניסוח המדויק.

P56 · אבטחת Web

בהקשר של אתר HTTPS רגיל, איזה תיאור מבחין נכון בין HttpOnly לבין Secure בעוגיית סשן?

  1. א. HttpOnly מגביל גישה לעוגייה מתוך JavaScript; Secure מגביל את שליחתה לחיבור מאובטח
  2. ב. Secure מונע כל קריאה מ-JavaScript; HttpOnly מצפין את העוגייה במסד הנתונים
  3. ג. שני הדגלים מונעים מהדפדפן לצרף את העוגייה לבקשה שיוזם XSS
  4. ד. HttpOnly לבדו מחייב את הדפדפן לשלוח את העוגייה רק ב-HTTPS

התשובה הנכונה כאן: א. HttpOnly מגביל גישה לעוגייה מתוך JavaScript; Secure מגביל את שליחתה לחיבור מאובטח

דרך הפתרון

לכל דגל מטרה אחרת. HttpOnly מונע חשיפה רגילה של העוגייה דרך ממשקי script כגון document.cookie. Secure מגביל את השימוש בעוגייה בהקשר תעבורה מאובטח. אף אחד מהם אינו מבטיח שקוד XSS לא יוכל לבצע בקשות באתר כאשר הדפדפן מצרף את הסשן בעצמו.

למה התשובה נכונה ולמה שאר האפשרויות שגויות

מזהים כל חלופה לפי הטקסט שלה; אותיות התשובות משתנות בערבוב.

נכונה — HttpOnly מגביל גישה לעוגייה מתוך JavaScript; Secure מגביל את שליחתה לחיבור מאובטח

ההבחנה מפרידה בין גישה מתוך script לבין תנאי שליחת העוגייה ברשת. אלה הגנות משלימות ולא אותו מנגנון.

שגויה — Secure מונע כל קריאה מ-JavaScript; HttpOnly מצפין את העוגייה במסד הנתונים

Secure אינו הדגל שחוסם document.cookie, ו-HttpOnly אינו הוראה למסד נתונים להצפין מידע. שני התפקידים הוחלפו כאן.

שגויה — שני הדגלים מונעים מהדפדפן לצרף את העוגייה לבקשה שיוזם XSS

XSS יכול ליזום בקשות באותו אתר בלי לקרוא ישירות את העוגייה. הדפדפן עשוי לצרף אותה בהתאם לכללים גם אז.

שגויה — HttpOnly לבדו מחייב את הדפדפן לשלוח את העוגייה רק ב-HTTPS

HttpOnly עוסק בגישה מתוכנה בדפדפן. ללא תנאי Secure מתאים אין ממנו לבדו דרישה שהתעבורה תהיה HTTPS בלבד.

דגש והנחות שחשוב לזכור

השאלה מניחה שירות HTTPS רגיל ואינה עוסקת בחריגי סביבות פיתוח. מניעת XSS, בדיקות הרשאה והגנות CSRF עדיין נדרשות לפי ההקשר. היכולת לקרוא cookie והיכולת להפעיל סשן באמצעות בקשה הן יכולות שונות.

מקורות לבדיקת המנגנון: RFC 6265 — Secure and HttpOnly
