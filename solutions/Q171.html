Q171 · רשתות: ARP, DNS, DoS ו-Firewall

מה מבין הדברים הבאים יוכל לבצע תוקף בעל יכולות MITM, ללא מידע נוסף?

  1. א. לזייף חתימה דיגיטלית של אחד מהצדדים.
  2. ב. יוכל לגנוב את ה coinbase transaction, כלומר, יוכל לשנות את התגמול שאמור לקבל ה miner שמצא את הבלוק כך שהתגמול יוענק לתוקף במקום.
  3. ג. יוכל לשנות דפי HTML שמועברים על גבי חיבור HTTPS שכבר הוקם בין שרת ולקוח.
  4. ד. יוכל לשנות כתובות IP בתשובות לשאילתות DNS שאינן cached.

התשובה הנכונה כאן: ד. יוכל לשנות כתובות IP בתשובות לשאילתות DNS שאינן cached.

פתרון חדש שנכתב ונבדק במסגרת עדכון נובמבר 2026

לפי מודל הקורס של DNS רגיל לא מאומת, MitM יכול לשנות כתובת בתשובת DNS. אם התשובה עוברת דרכו ואינה מוגנת באימות מתאים, הוא יכול להחליף את המידע שמוחזר לקורבן. האזכור של שאילתה שאינה cached נועד לכך שיש תעבורת רשת חדשה לתקוף.

לעומת זאת, נוכחות בנתיב אינה נותנת מפתחות TLS. שינוי דפי HTML בתוך חיבור HTTPS מאומת שהוקם כראוי אמור להיכשל בבדיקת שלמות. תוקף יכול לחסום תעבורה ולפגוע בזמינות, אבל זו אינה אותה פעולה כמו שינוי שקוף בתוכן שהלקוח יקבל כאותנטי.

שינוי תגמול ה-coinbase בבלוק שנכרה משנה את התחייבות הבלוק לטרנזקציות ומחייב הוכחת עבודה תקפה מחדש. היכולת להעביר חבילות אינה מאפשרת ״לגנוב״ את הבלוק תוך שימור ה-hash התקף. גם זיוף חתימה דיגיטלית אינו נובע ממיקום התוקף ברשת.

החלופה הראשונה אינה משפט נכון לכל פריסת DNS בעולם: אימות DNSSEC או ערוץ DNS מוגן עשויים למנוע שינוי מקובל אצל לקוח שמאמת נכון. אלה הנחות נוספות שלא ניתנו בשאלה. בפתרון חשוב לציין את מודל הפרוטוקול ולא להרחיב את ״MitM״ לכוח בלתי מוגבל. זהו חיבור שימושי בין שאלות ARP, DNS ו-TLS: השגת מיקום בנתיב היא שלב אחד, ושבירת קריפטוגרפיה מאומתת היא שלב אחר.
